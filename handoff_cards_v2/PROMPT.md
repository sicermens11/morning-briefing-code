작업 원칙:

1. **참조 구현은 규격의 근거이지 정답이 아니다. 위 셋은 반드시 걸러라.** 픽셀을 베끼지 말고 SPEC.md의 규격을 `scripts/card_theme_v2.py`(새로 만드는 카드 전용 테마)와 `build_cards.py`에 적용해라.** `card_theme.py`의 공유 부품은 개조하지 마라. `card_theme.C`는 밝은 배경용이라 그대로 쓸 수 없다 — 새 색은 SPEC 5절 표를 `card_theme_v2`에 정의해라. 세로 상세(`build_scroll.py`)는 이번 변경에서 건드리지 마라.
2. **문장·수치는 원문 그대로.** 넘치면 요약하지 말고 여백·크기·블록 배치로 맞춰라.
3. **카드 래퍼는 `section[data-label]` 그대로.** `div`나 다른 속성명으로 바꾸면 `check_layout`이 카드를 0개 찾고도 통과해서, 전 카드가 잘려도 게시된다.
4. **mono 글꼴 금지.** Pretendard + `font-variant-numeric:tabular-nums`.
5. **`build_cards.py`의 90~305줄(데이터·서식 함수)은 건드리지 마라.** 세로 상세가 거기서 아홉 개를 가져간다 — `GRADE` `LOG` `WEEKDAY` `_copy` `_f` `_snap` `entry_text` `pg` `dcolor`. 특히 `pg(num, total)`은 인자를 그대로 둬라(`total`을 안 쓰지만 없애면 `build_scroll`이 깨진다). 305줄 아래 렌더링만 갈아엎어라.
6. **작업 순서:** ① 교체 전 현재 8장 스크린샷 확보 → ② `card_theme_v2.py` 신설 → ③ 커버·02장만 먼저 바꿔서 `check_layout` 통과 확인 → ④ 나머지 카드 → ⑤ 엣지 케이스(**후보 1개인 날부터** — 다섯 날 중 하루라 제일 흔하다).
