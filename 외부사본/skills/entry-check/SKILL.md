## STEP 1: 조건 판정 (MCP 호출 0회)

```powershell
& "C:\Users\mrblue\Claude\morning breifing_code\scripts\run-py.ps1" -Script check_entry.py -Args @('--save','--slot','0905','--orderbook','C:\Users\mrblue\Claude\morning breifing_code\data\orderbook-today.json')
```
⚠️ STEP 0.5가 실패해 파일이 없으면 `--orderbook` 두 인자를 빼고 그대로 실행한다.

스크립트가 하는 일:
1. `data\briefing-daily-log.jsonl`에서 오늘 항목을 찾는다
2. 각 픽의 `entry_conditions`를 네이버 실시간 시세와 대조한다
3. 판정 결과를 `data\entry-check-log.jsonl`에 저장한다(백테스트 표본 축적)

반환 필드:
- `verdict` — `조건충족` / `보류` / `철회검토` / **`확인필요`** / `확인불가`
- `gap_pct` — **시초가가 전일종가 대비 몇 %인지.** 이 판정의 핵심 지표다
- `change_from_found` — 발굴가 대비 등락
- `conditions[]` — 조건별 `met` 여부와 실제값
- `호가` — `최우선매도` · `최우선매수` · `스프레드pct` · `매도매수잔량비` · `최우선매도잔량`
  ⚠️ **기록용이다.** 판정에 안 쓴다. 화면 띠에는 **스프레드만** 한 조각 나간다.

⚠️ `ok: false`면 오늘 브리핑 항목이 없는 것이다 → 그 사실만 STEP 3에 남기고 종료.

### ⚠️ `_경고`가 있으면 반드시 실행 요약에 남긴다

응답에 `_경고.진입조건_미기록`이 있으면 **아침 브리핑이 진입 조건 숫자를 JSONL에 안 쓴 것**이다.
해당 픽은 `확인필요`로 나오며, **절대 "조건충족"으로 바꿔 쓰지 않는다.**

왜 중요한가: 브리핑 본문에는 "20일선 26,235원 회복 후 진입"이라고 써놓고 JSONL에만 빠뜨리는
경우가 있을 수 있다. 그때 "조건 없음 = 조건충족"으로 처리하면 **조건이 있는데도 진입 신호를
보내는 오판**이 된다. 그래서 "조건을 안 쓴 것"과 "조건이 없다고 명시한 것"을 구분한다.

| 상태 | verdict | 뜻 |
|---|---|---|
| 조건 있고 전부 충족 | `조건충족` | 그대로 진입 판단 |
| 조건 있고 하나라도 미충족 | `보류` | 미충족 항목을 실행 요약에 명시 |
| `entry_conditions: []` (없음을 명시) | `조건충족` | 브리핑이 조건 없음을 확인한 것 |
| **필드 자체가 없음** | **`확인필요`** | **판정 불가 — 브리핑 본문을 직접 보라고 알린다** |

`확인필요`일 때 실행 요약 문구 예:
```
❓ 성광벤드 23,400 — 진입조건 미기록, 메일 본문 확인 필요
```

## ⚠️ 09:05에 믿을 수 있는 것과 없는 것

개장 직후 5분은 노이즈 구간이다. 그래서 **이 시각에 흔들리지 않는 값만** 본다.

| 믿을 수 있음 | 09:05엔 무의미 |
|---|---|
| **시초가** — 동시호가로 확정된 단일가 | 오늘 추세 |
| 시초가 vs 전일종가 갭률 | 당일 외국인·기관 수급 |
| 20일선·지지선 대조 (절대 가격) | 거래량 비율 |

→ **추세·수급 이야기를 쓰지 않는다.** 그건 12:20 슬롯의 몫이다.
→ 09:05 판정의 질문은 하나다: **"재료가 시초가에 이미 반영됐나?"**

**갭률이 +5% 이상이면 `철회검토`가 나온다.** 브리핑이 "아직 미반영"이라던 재료가 개장 순간
가격에 다 들어갔다는 뜻이고, 그러면 갭 전략의 전제 자체가 무너진 것이다.
(2026-08-21 대창솔루션이 수주 공시 당일 +19.11% 급등하며 재료를 그날 안에 소화한 사례가 있다.)
