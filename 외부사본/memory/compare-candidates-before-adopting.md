같은 날 후보 **둘**이 4관문을 지났는데, 하나를 먼저 반영하고 **그 뒤에** 견줬다.
견줘 보니 나중 것이 셋 다에서 앞섰고, 둘을 같이 켜면 **먼저 넣은 것이 아무 일도 안 했다.**
결국 반영을 되돌렸다 (2026-09-21).

```
① ㉥ 빠지는 장엔 더 산다   107% · 낙폭 -10.5% · 산 것 340   ← 먼저 반영함
② ㉦ ㉢ 문턱 (-5,-13)     109% · 낙폭  -7.7% · 산 것 365
④ ①+②                   109% · 낙폭  -7.7% · 산 것 365   ← ② 와 **소수점까지 같다**
```
㉦ 가 60일 문턱을 조여 후보 날이 줄면, 그런 날엔 하루 자리를 늘려도 **채울 후보가 없다.**

**Why:** 규칙 변경은 서로 **같은 곳을 건드리는** 일이 많다.
「빠진 날에 더 산다」와 「빠진 날을 좁힌다」처럼 정반대로 작동하면 하나가 무력해진다.
따로 재서 둘 다 좋아도 **같이 켠 값은 따로 재야 안다** ([[dont-add-conditions]]).
반영은 실전 코드·화면 문구·성적표·빈도를 다 건드려서 되돌리는 값이 싸지 않다.

**How to apply:**
1. 한 판에서 후보가 **둘 이상** 통과하면 **반영하지 말고 먼저 견준다.**
   ① A만 ② B만 ③ A+B 를 나란히. ③ 이 ①·② 보다 나아야 둘 다 넣는다.
2. ③ 이 ② 와 **같은 값**이면 A 는 무력한 것이다 — 나은 하나만 쓴다. 규칙도 단순해진다.
3. 견줌은 **옛 규칙**(둘 다 없던 상태)으로 둔다. 새로 넣은 것을 견줌으로 쓰면 비교가 흐려진다.
4. 반영 순서: **견주기 → 사용자 선택 → 반영 → 대조기(rule_align) → 성적표·빈도 다시 만들기 → 화면**.

⚠️ 화면 문구를 바꿀 때 `rule_align` 이 정규식으로 찾는 자리를 깨뜨리지 마라.
   2026-09-21 에 「최대 N종목 지정가」 사이에 괄호를 끼워 **그 검사가 통째로 죽었다.**
   대조기가 「못 찾았다 — 이대로 두면 영영 검사되지 않는다」로 잡아 줘서 알았다.
