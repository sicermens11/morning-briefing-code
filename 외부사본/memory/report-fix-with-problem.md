**문제를 말할 때는 「문제 → 조치 → 결과」를 한 묶음으로 쓴다.** 문제만 나열하지 않는다.

2026-09-01 밤, 밤샘 스크립트에서 버그 5개를 찾아 **전부 고쳐놓고도** 보고할 때는 문제만 적었다. 사용자가 되물었다: *"저녁 수집이 평일에도 통째로 건너뛸 수 있었는데 어떻게 된거야? 뭔가 바꾼거야?"* · *"④⑤ 이것도 헛돌았는데 어떻게 조치한거야?"* 그리고 마지막에: ***"문제만 얘기하지 말고 어떻게 할건지, 해결했다면 어떻게 한건지도 같이 설명해! 문제만 말하면 왜 말하는거야"***

**Why:** 문제만 들으면 사용자는 **아직 안 고쳐진 것으로 읽는다.** 그러면 불안해서 되묻거나, 스스로 대책을 세우려 한다 — 이미 끝난 일에 시간을 쓰게 만든다. 나는 "발견했다"를 성과로 보고했지만 사용자에게 성과는 **"고쳤다"**다.

**How to apply:**
- **세 줄로 쓴다.** `문제 → 조치(구체적으로 무엇을 어떻게) → 결과(숫자로)`. 예: *"한도 21,200회 > 20,000회 → 배당을 빼고 --상한 5400을 걸었다 → 15,900회, 브리핑 몫 4,100회 남김."*
- ⚠️ **조치를 "고쳤다"로만 쓰지 않는다.** 무엇을 어떻게 바꿨는지 적는다 — 정규식이면 바뀐 패턴을, 설정이면 바뀐 값을, 순서면 바뀐 순서를.
- **아직 안 고쳤으면 그렇다고 명시한다.** "고칠 예정" / "사용자 결정 필요"를 구분해 쓴다.
- **고칠 수 없는 것도 그 자리에서 닫는다** — "재료가 없어 못 한다"까지 쓰고 상태를 바꿔 적는다([[record-decisions-and-tasks]]).
- 사용자가 반복해 말한 것: *"문제만 얘기하지말고 내가 선택할 수 잇게 해결방안을 얘기해."* **선택지를 줄 때도 같다** — 안1·안2만 던지지 말고 맥락부터([[context-before-options]]).
