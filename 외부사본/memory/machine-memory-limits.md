시험 판을 띄우기 전에 보는 숫자는 **물리 메모리가 아니라 커밋 여유**다.

```
2026-09-20 00:19 · combo4 한 판이 도는 중에 잰 값
    물리    남음  1.4 GB / 31.9 GB
    커밋    쓴 것 43.8 GB / 한도 45.3 GB   ← 여유 1.5 GB 뿐
    판 하나 커밋  31.7 GB · 작업셋 24.0 GB
    페이지  C:\pagefile.sys  할당 13.3 GB · 최고 쓴 것 7.4 GB
```

| 판 | 작업셋 | 도는 시간 |
|---|---|---|
| combo4_lab.py (재료 판 · 사건 540만) | **24 GB** | **9시간** |
| gate7_lab.py (자본 시뮬 · 사건 73만) | 16~23 GB | 1~2시간 |

**Why:** 커밋 한도 = 물리 + 페이지 파일이다. 한도를 넘으면 파이썬이 MemoryError 로 **죽는다**.
물리 여유만 보면 멀쩡해 보이는데 커밋이 다 찬 경우가 있다 — 위 값이 정확히 그 상황이다.
그리고 「큰 파이썬이 0 인가」만 보는 건 **앞 판이 끝났나**일 뿐, OS 가 커밋을 돌려줬나는 안 본다.

**How to apply:**
1. 판을 띄우기 전에 `메모리관문 18` — 커밋 여유가 18GB 될 때까지 기다린다.
   `queue_knob.ps1` · `queue_decide.ps1` 에 들어 있다. 새 줄 스크립트에도 같이 넣는다.
   재는 법: `(Get-CimInstance Win32_OperatingSystem).FreeVirtualMemory / 1MB` (GB 단위)
2. **판은 언제나 하나만.** 두 개가 겹치면 커밋 한도를 확실히 넘는다.
3. 페이지 파일은 **시스템 자동 관리(자동 확장 True)**이고 C: 에 47GB 가 남아 있어
   한도가 따라 오른다. **설정을 건드리지 마라** — 재부팅이 걸리면 돌던 판이 날아간다.
4. 판 시작 전·끝난 뒤 메모리를 로그에 남긴다. 다음에 얼마나 쓰는지 알려면 기록이 있어야 한다.
5. combo4 의 24GB 는 **사건 540만 개를 dict 로 들고 있어서**다. 줄이려면 표현을 바꿔야 하는데
   큰 고침이라 **판이 도는 중에는 손대지 않는다.**
