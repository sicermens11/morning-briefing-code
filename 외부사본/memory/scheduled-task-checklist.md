예약 작업(작업 스케줄러)을 새로 만들거나 고칠 때 **다섯 가지를 반드시 확인한다.**
안 되어 있으면 작업이 **조용히 안 돌고, 예약 목록에는 정상으로 보인다.**

```
① python.exe를 **전체 경로**로      NightLabs0904가 이것 때문에 실패(코드 2147942402)
② WakeToRun · StartWhenAvailable    절전이면 안 깨어난다
③ StopIfGoingOnBatteries=false      (이 PC는 데스크톱이라 무관하지만 습관)
④ RestartCount 3 / 10분             한 번 죽으면 그걸로 끝나지 않게
⑤ **주말·휴장일 가드**              장 안 서는 날 돌면 낡은 자료로 결과를 덮어쓴다
```

⑤는 **스크립트 안 가드로 끝내지 말고 트리거 요일까지 본다.** 2026-09-14에
`MorningSectorBriefing` 혼자 **Daily**로 걸려 있어 9/12(토)·9/13(일)에도 돌았다
(나머지 셋은 월~금 = **요일마스크 62**). 지난 주말들에 안 돈 건 예약이 달라서가
아니라 **PC가 꺼져 있어서**였다 — 켜 두자 바로 드러났다.
피해가 실제로 있었다: 토요일 브리핑이 **월요일 재료를 먼저 먹어** 일요일 후보가
0개가 됐다(「금요일 마감 후 나온 소식은 9/12 브리핑이 이미 소화해 갭①②가 모두 소진」).
⚠️ **예약 변경은 관리자 권한이 필요하다** — 보통 창에서는 `Set-ScheduledTask`가
`Access is denied`로 죽는다. 사용자에게 돌려 달라고 할 `.ps1`을 만들어 주고,
**utf-8-sig로 쓴다**(PowerShell 5.1은 BOM 없는 UTF-8을 cp949로 읽어 한글이 깨진다).
전체 경로를 `& "..."`로 감싸 알려 준다 — 폴더 이름에 공백이 있다.

**Why:** 2026-09-01 18:09에 PC가 비정상 종료(Kernel-Power 41)됐는데 **아무도 몰랐다.**
예약은 「돌았다」로 표시된다. 여러 시간짜리 작업이 통째로 날아가도 로그에만 남는다.

**How to apply:** 여러 시간 도는 묶음 작업은 **이어 돌기**를 넣는다 —
결과 파일이 성하면(2KB↑·Traceback 없음·끝맺음 있음) 건너뛴다.
⚠️ 이때 **오늘 날짜만 보면 안 된다.** 예비 트리거가 다음 날 돌면 어제 파일을
못 찾고 전부 다시 돈다 — 최근 3일치를 본다. (`weekend_labs.py:이미끝났나`)
매일 도는 [[daily-selfcheck-covers]] selfcheck.py G·H절이 비정상 종료와
예약 실패 코드를 감시한다.
