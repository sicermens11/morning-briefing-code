**판정 기준은 시험 설계의 절반이다.** 내가 임의로 넣은 숫자 한 줄이 결론을 뒤집었다.

2026-09-09~10에 같은 실수를 세 번 했다:

```
191차   「1년에 최소 3개는 나와야 쓸 만한 규칙」   <- 내가 그냥 넣은 숫자
        => 「1년 9개」짜리(그 섹터 지금 규칙의 28%)가 통과했다
        사용자: 「이건 왜 이렇게 규칙인거야? **1년에 최소 3개면 너무 적잖아?**」

185차   걷기 검증이 **이김만** 봤다
        => 1년 42개(80.7%)가 1년 2,115개(53.6%)를 이긴 것으로 찍혔다.
           **기회가 2%**로 줄었는데 「나눠서 배우면 낫다」는 결론이 나왔다
        기회 수를 넣자 **41개 전부 탈락**

190차   4관문 A절도 이김만 봤다 => 기회가 **6~37%**로 줄어든 것이 「7개 전부 통과」로 찍혔다
```

**Why:** 판정 기준이 사용자 원칙과 어긋나면, 시험이 아무리 정확해도 **결론이 거꾸로 나온다.**
여기서 사용자 원칙은 「**상승 기회를 놓쳐서는 안 된다**」인데, 내 기준은 늘 승률만 봤다.

**How to apply:**
- 새 시험을 만들 때 **판정 기준을 먼저 한 줄로 적어 사용자에게 보인다** —
  「이 시험은 ○○가 △△보다 크면 통과로 봅니다」
- 절대 개수(「1년 3개」)가 아니라 **지금 규칙 대비 비율**로 잰다
- 승률을 보는 모든 자리에 **기회 수를 나란히 찍는다**
